## Reading the scorecard

- **FAIL does not mean "broken everywhere"** — it means the category cannot support a launch claim on current evidence. Backend reliability FAILs on one decisive fact (purchase path cut + 0/20 production checks), even though 9/12 functions are deployed and much code is fixed.
- **PASS_WITH_CONCERNS is the honest middle:** the code is largely there (StoreKit, admin UI, tests, RLS), but wiring, deployment, or verification is missing.
- **NOT_VERIFIED is a scope statement, not a pass:** performance cannot be judged from this VM at all, and the audit marks that rather than guessing.
- **Cross-reference:** every row traces to Report 4 (Supabase), Report 5 (security), Report 8 (testing/CI), Report 9 (historical gates), and the worker files in `working/`.
