### 3.2 Where AI should suggest vs where deterministic data must stay authoritative

This is the most important design line in the report. ASCND already has the right instinct (deterministic readiness engine + AI as a chat layer); the competitors show where the line should be drawn harder.

| Decision | Authority | Why |
|---|---|---|
| Readiness score, ACWR, load, HRV/RHR/sleep subscores | **Deterministic engine only. AI never recomputes or overrides.** | These are measurements with published formulas. An LLM "recomputing" them is hallucination with a friendly tone. WHOOP/Oura both keep scores algorithmic and let the LLM *explain* them. ASCND's engine is already correct here — protect it. |
| Calorie/macro/water targets, BMR/TDEE | **Deterministic formulas only** (Mifflin-St Jeor etc.). AI may explain or suggest *which* foods, never the numbers. | Same reason. MFP's Meal Planner gets this right: AI picks recipes *within* deterministic targets. |
| "How many calories / protein did I eat?" | **Deterministic log only. Never "0" when unlogged.** | ASCND's K-03 is exactly this failure. Oura/WHOOP answer from data or say "not logged". The fix is a null-is-not-zero rule enforced in every AI surface (KOA-T03). |
| Allergies, dislikes, diet, medical flags | **Deterministic filter, applied *before* the LLM sees the request.** | K-02: the profile block dropped these. The correct architecture is a hard filter (allergen → dish excluded, no LLM discretion) + the LLM choosing among survivors. MFP does this; ASCND must. |
| Workout plan generation (exercises, sets, reps, load) | **Deterministic progression engine as the skeleton; AI as the explainer/adapter.** | Fitbod/Freeletics/Apple Gym Strength all converge on this: the plan is an algorithm (progressive overload, recovery modelling, periodisation); the LLM explains, motivates, and handles edge cases ("rack taken — swap?"). A pure-LLM plan generator invents loads and is a safety risk. ASCND has the skeleton pieces (LoadHint, OverloadPlan, LighterSession, e1RM) but no *generating* engine — that engine should be deterministic first (O-01). |
| Form guidance | **Deterministic reference (measured motion) + AI for cue selection, never for inventing technique.** | ASCND's Motion Kit already does this correctly (approval by reference-comparison, not expert review; 3D guides from measured clips). AI form *analysis* from camera (Freeletics claims it) is **INVESTIGATE_FURTHER** — accuracy unverified publicly, privacy-sensitive. |
| "Why did my score dip?" / trend interpretation | **AI's best job.** LLM reads deterministic numbers + journal + history and narrates the likely contributors, with uncertainty stated. | WHOOP Activity Insights and Oura Advisor's in-chat graphs are the model. ASCND's coach *should* do this but K-33 shows it lacks the context (no water, no steps, streak capped at 7, only first check). |
| Nudges / notifications | **Deterministic triggers + AI wording.** | SmartNudges already does this (max 4 AI calls/day + deterministic fallback). WHOOP's proactive check-ins are the same pattern. The trigger (readiness dropped, 3 poor sleeps) must be a rule; only the sentence is generated. |
| Meal suggestions | **AI proposes; deterministic targets + allergy filter constrain.** | ASCND's ai-meal-suggest exists; the missing piece is the constraint layer (K-02) and a real plan generator (O-10). |
| Conversation, motivation, education | **AI, freely.** | Lowest risk, highest perceived value. Tone choice (Oura) applies here. |

### 3.3 Hallucination, privacy, safety — risks and mitigations

- **Hallucination:** Oura states it plainly ("Advisor can make mistakes"). ASCND's mitigations must be structural, not prompt-only: (1) every AI answer that cites a number must cite it from a *verified context block* (CoachOverviewCheck exists — extend it, K-33); (2) numbers never generated, only quoted; (3) truncation-as-success fixed (K-06); (4) error classification that actually reads the body (K-07); (5) a visible "AI can be wrong — check your log" affordance on numeric answers. **Never let the coach state a load, a calorie target, or a medical interpretation as its own conclusion.**
- **Safety / medical boundary:** WHOOP/Oura both carry "not a medical device" positioning and (Oura) a dedicated women's-health model built with clinicians. ASCND's CoachHealthTopic disclaimer is word-list based and shows only on the last assistant message (K-36) — weak. The fix is a *topic* classifier (deterministic, not word-list) + persistent disclaimer in health-topic threads + escalation copy ("talk to a clinician") for red-flag topics (chest pain, eating-disorder language, injury). This is a P1 safety item, not a nice-to-have.
- **Privacy:** WHOOP's My Memory and Oura's Memories both let users **view, edit and delete** everything the coach remembers. ASCND has CoachMemoryView (view/delete) — parity exists, but K-32 shows the visible set ≠ the used set (unknown-kind facts hidden from the user but sent to the model). Fix: visible set = used set, always. Also: ASCND's edge functions already keep the LLM server-side (app never calls the LLM directly) — keep it that way; on-device inference is not needed and would leak the model boundary. Health data sent to the LLM must be minimised to the context block (no raw HealthKit dumps), and the existing `ai_gate`/`spend_ai_tokens` quota stays as the abuse control.
- **The probe problem (K-08):** ASCND hides *all* AI entries when the `ai-coach` probe fails. Competitors degrade gracefully (Oura: Advisor unavailable *in that spot*, numbers still shown). ASCND should do the same: AI entries degrade to deterministic content, never vanish.
- **Cost/dependency:** ASCND's `callAI` has 3-provider failover (server-side, good). The client 90s idle timeout mislabels slow AI as offline (K-09) — fix the timeout to exceed worst-case failover, don't shorten the failover.
